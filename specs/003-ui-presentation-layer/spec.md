## Clarifications

### Session 2026-11-09

- Q: 旋转与裁剪这两个几何调整，在单页编辑界面中本期承载到什么程度？ → A: B——旋转以角度控件进界面（随动态面板生成）；裁剪本期不做（滑块面板排除裁剪入口，引擎能力保留）。总体取向：本期先简化，简要完成课程设计的要求。
- Q: 导出成品时，文件应如何到达用户手中？ → A: B——导出到固定输出目录（如项目 `output/`），免输入路径，界面在成功反馈中显示成品完整保存位置。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 打开图片查看预览与直方图 (Priority: P1)

用户在单页编辑界面选择（或上传）一张本地图片，画布区显示该图片的预览，直方图面板同步显示 RGB 三通道分布。这是整个编辑流程的入口，没有它其余功能无从演示。

**Why this priority**: MVP 核心——打开是编辑与导出的前置条件，也是课程验收演示的第一步。

**Independent Test**: 可在浏览器中打开页面、选择一张样图，独立验证「预览呈现 + 直方图渲染 + 文件名显示」；不依赖任何编辑功能。

**Acceptance Scenarios**:

1. **Given** 页面已加载且未打开图片，**When** 用户通过打开入口选择一张合法图片，**Then** 画布呈现图片预览（先低分辨率后高分辨率自动替换）、直方图面板渲染三通道分布、界面显示文件名
2. **Given** 页面已加载且未打开图片，**When** 用户尚未选择图片，**Then** 画布区呈现空状态提示而非空白或报错

---

### User Story 2 - 滑块调整实时预览 (Priority: P1)

用户拖动某个调整滑块（如亮度、对比度），画布预览随即更新：先快速呈现低分辨率效果，随后自动替换为高分辨率效果；直方图随预览同步刷新。滑块的刻度范围与默认值来自界面加载的参数模式，不写死在组件里。

**Why this priority**: 「拖滑块实时预览」是本项目（简化版 Lightroom）的核心卖点与 M4 里程碑验收场景。

**Independent Test**: 可在已打开图片的会话中拖动单个滑块，独立验证「预览渐进更新 + 直方图刷新 + 滑块显示当前值」。

**Acceptance Scenarios**:

1. **Given** 已打开图片，**When** 用户拖动亮度滑块至某值并松开，**Then** 画布先呈现低分辨率预览再自动替换为高分辨率预览，直方图随之刷新
2. **Given** 已打开图片，**When** 用户快速连续拖动同一滑块多次，**Then** 界面最终稳定显示最后一次值的预览（中途状态不残留）
3. **Given** 已打开图片，**When** 用户查看滑块面板，**Then** 每个滑块的可调范围与初始位置与参数模式一致（亮度/对比度/饱和度/锐化/色温为比例因子型滑块；旋转以角度控件呈现；裁剪本期不提供界面入口）

---

### User Story 3 - 撤销与重做同步交互 (Priority: P2)

用户点击撤销/重做控件，画布预览回退/前进，滑块位置同步回到对应状态（被撤销的调整回到默认位置，重做后恢复），无需手动刷新。

**Why this priority**: 编辑体验的完整性；依赖 US1/US2 建立的会话，但验收不依赖导出。

**Independent Test**: 可在已做若干调整的会话中独立验证「撤销后滑块与预览同步回退，重做后恢复」。

**Acceptance Scenarios**:

1. **Given** 已做至少一次滑块调整，**When** 用户点击撤销，**Then** 预览回退至上一步、对应滑块回到调整前位置
2. **Given** 已撤销至少一步，**When** 用户点击重做，**Then** 预览与滑块位置恢复到被撤销前的状态
3. **Given** 无可撤销操作，**When** 用户点击撤销，**Then** 界面呈现可读提示，预览与滑块位置保持不变

---

### User Story 4 - 导出成品 (Priority: P2)

用户通过导出控件选择输出格式（JPEG/PNG），一键导出到固定输出目录（免输入路径）；导出期间界面呈现进行中状态，完成后给出成功反馈（含成品完整保存位置）；成品与编辑会话描述文件由引擎落盘。

**Why this priority**: 闭环「打开 → 编辑 → 导出」主流程的最后一环，依赖已有会话。

**Independent Test**: 可在已编辑的会话中独立执行导出，验证「成品文件生成 + 成功反馈 + 重复导出可用」。

**Acceptance Scenarios**:

1. **Given** 已打开图片（无论是否调整），**When** 用户选择格式并确认导出，**Then** 界面先呈现「导出中」，完成后显示成功消息与成品完整保存位置，输出目录出现成品文件
2. **Given** 导出进行中，**When** 导出尚未结束，**Then** 导出控件呈现忙碌状态，避免重复触发造成困惑

---

### User Story 5 - 错误反馈与忙碌指示 (Priority: P3)

任何操作失败（打开损坏文件、不支持格式、越界参数、导出失败、空栈撤销）都以界面消息呈现，不打断当前会话；处理期间界面呈现忙碌指示。用户看到错误后可以直接继续正常操作，无需刷新页面。

**Why this priority**: 健壮性兜底；依赖前四个故事建立的交互面。

**Independent Test**: 可在任意会话状态下独立触发失败操作，验证「错误消息呈现 + 界面状态保持 + 后续操作正常」。

**Acceptance Scenarios**:

1. **Given** 任意会话状态，**When** 用户执行一个注定失败的操作（如打开不支持的文件），**Then** 界面显示可读错误消息，已有预览与滑块状态保持不变
2. **Given** 界面正显示一条错误消息，**When** 用户执行下一次成功操作，**Then** 旧错误消息被清除
3. **Given** 处理进行中，**When** 用户观察界面，**Then** 忙碌指示可见；处理结束后指示消失

### Edge Cases

- 未打开图片时，滑块面板、撤销/重做、导出控件如何呈现？（空状态禁用或提示，不得报错）
- 打开损坏或解码失败的文件时，界面如何保持既有会话？
- 滑块拖动到极值时，预览与直方图是否仍正常更新？
- 输出目录不可写或被占用时，错误反馈是否指明原因且无崩溃？
- 页面刷新导致会话重置时，界面是否回到干净的空状态而非报错？
- 处理忙碌期间用户再次触发同类操作，界面如何避免状态错乱？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供单页编辑界面作为应用入口路由，承载「打开 → 编辑 → 导出」全流程，无需页面跳转
- **FR-002**: 系统 MUST 提供图片打开入口，用户可通过其选择本地图片文件
- **FR-003**: 画布 MUST 显示当前预览，并按「先低分辨率、后高分辨率自动替换」的渐进方式呈现
- **FR-004**: 直方图面板 MUST 随预览刷新渲染 RGB 三通道分布（各通道 256 档）
- **FR-005**: 滑块面板 MUST 依据加载的参数模式动态生成调整控件——比例因子型调整渲染为滑块、角度型调整（旋转）渲染为角度控件（可调范围、默认值均来自模式数据，不写死于组件）；框型参数（裁剪）本期不渲染界面入口；调整名以注册原名展示，不做本地化
- **FR-006**: 滑块等交互 MUST 仅通过调用桥接层暴露的事件处理器转发用户操作，组件自身不包含业务规则
- **FR-007**: 系统 MUST 提供撤销/重做控件，操作后滑块位置与预览 MUST 与界面状态同步回退/前进
- **FR-008**: 导出控件 MUST 支持选择输出格式（JPEG/PNG），一键导出到固定输出目录（免输入路径）并在成功反馈中显示成品完整保存位置，呈现导出中、成功、失败三种反馈
- **FR-009**: 所有操作失败 MUST 以界面消息呈现可读原因，不中断会话；下一次成功操作 MUST 清除旧错误消息
- **FR-010**: 处理进行中 MUST 呈现忙碌指示，处理后消失
- **FR-011**: 未打开图片时 MUST 呈现空状态提示；各控件在该状态下不得产生报错
- **FR-012**: 界面层 MUST 仅依赖界面框架与桥接层暴露的方法——禁止引入任何图像处理库，禁止直接调用引擎内部 API
- **FR-013**: 组件 MUST 为哑组件：数据经属性注入、事件经回调上抛，组件不持有业务状态、不含业务分支逻辑

### Key Entities *(include if feature involves data)*

- **编辑页（单页）**: 应用唯一页面；组合画布、直方图、滑块面板、菜单/导出控件，绑定桥接层状态与事件处理器
- **预览画布组件**: 呈现当前预览图（数据 URL），无内部业务状态
- **直方图组件**: 接收三通道分布数据渲染柱状分布，无内部业务状态
- **滑块面板 / 单滑块组件**: 面板按参数模式组合多个单滑块；单滑块仅接收取值范围/当前值并上抛变更事件
- **文件菜单栏组件**: 承载打开入口与导出入口
- **导出对话框组件**: 承载格式选择、目标位置与导出反馈
- **桥接层绑定**: 页面将桥接层状态变量注入组件属性、将桥接层事件处理器注入组件回调——组件与引擎之间唯一的合法通道

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 打开合法样图后，预览与直方图在 3 秒内完整呈现（本地环境）
- **SC-002**: 松开滑块后，高分辨率预览替换在低分辨率帧之后自动完成，全流程界面无需手动刷新
- **SC-003**: 「打开 → 调整 → 撤销 → 导出」全流程在同一页面内完成，全程零页面跳转、零手动刷新
- **SC-004**: 任意操作序列后，滑块显示值与界面呈现的参数状态完全一致（撤销回退、重做恢复均同步）
- **SC-005**: 界面层静态检查通过：界面目录中零图像处理库导入、零引擎内部直接导入（可纳入持续集成断言）
- **SC-006**: 全部组件满足哑组件约束：组件文件内无业务分支逻辑（评审/静态检查可验证）
- **SC-007**: 交付后既有测试套件保持全绿（桥接层 77 项、全量 250 项），界面改动不要求修改任何引擎层测试

## Assumptions

- 单页应用，无多路由导航（对应 M4 里程碑「桥接层 + 单页 UI」范围）
- 图片打开入口采用浏览器内上传控件（上传后交由桥接层打开）；开发调试场景允许直接输入本地路径
- 无会话持久化要求：页面刷新视为全新会话，界面回到空状态
- 目标环境为桌面浏览器（Chrome/Edge 最新版）；界面文案为中文
- 桥接层（002 交付）契约保持不变；若界面确需新增状态或处理器，仅允许 additive 扩展
- 视觉风格为简洁深色工作台（类 Lightroom），不做像素级还原
- 样式与布局细节（间距、配色、动效）不在本规格约束范围内，以可用性与红线合规为先

## Dependencies

- 001-core-engine-layer：核心引擎（打开/调整/撤销/重做/渲染/导出）
- 002-bridge-state-layer：桥接层（`FileState`/`DevelopState` 状态变量与事件处理器、渐进预览、错误通道、忙碌标志）
