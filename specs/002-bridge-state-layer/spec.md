# Feature Specification: PyLightroom 桥接层（State）

**Feature Branch**: `002-bridge-state-layer`

**Created**: 2026-11-09

**Status**: Draft

**Input**: User description: "桥接层（State） | `state/` | Reflex 状态定义、事件转发、把引擎结果转成 UI 可消费的数据 | 唯一允许同时 import Reflex 与核心引擎的层，只做「胶水」，不含业务规则"

## User Scenarios & Testing *(mandatory)*

本特性的「用户」是两类角色：**界面层集成者**（为哑组件接线的开发者——组件只从桥接层取数、只向桥接层抛事件）与**端到端使用者**（通过界面完成「打开 → 编辑 → 导出」的摄影师）。桥接层自身不渲染任何组件，全部能力可在无浏览器的命令行环境独立验证。

### User Story 1 - 打开照片后界面呈现可编辑视图 (Priority: P1)

作为界面层集成者，我在界面上接入「打开文件」动作后，只需读取桥接层暴露的绑定数据，就能让用户看到预览图、RGB 直方图、就绪的滑块初值与当前文件名——全程无需接触任何引擎 API，也无需自行协调「低分先出、高清后到」的时序。

**Why this priority**: 打开照片是一切编辑行为的入口；没有「引擎结果 → 界面可消费数据」的第一段桥，其余故事全部无从谈起。对应里程碑 M4（Reflex 集成）的第一步。

**Independent Test**: 在无浏览器环境构造状态对象、模拟一次「打开图片」事件并注入引擎回调，校验状态中预览数据（低分先行、高分替换）、直方图数据、滑块默认值、文件名依次就绪；仅需引擎门面即可完成，不依赖其余故事。

**Acceptance Scenarios**:

1. **Given** 一张有效图片，**When** 界面触发「打开」事件，**Then** 状态中的低分辨率预览数据先行可用，随后高清预览数据自动替换到位，全程无需用户刷新
2. **Given** 打开成功，**When** 界面读取绑定数据，**Then** 直方图数据（RGB 三通道分布）、各滑块默认值、当前文件名均已就绪且相互一致
3. **Given** 打开一个不支持格式或损坏文件，**When** 界面触发「打开」事件，**Then** 状态回写一条人类可读的错误消息，界面既有内容保持不变，应用不崩溃
4. **Given** 打开成功，**When** 界面组件代码检查自身依赖，**Then** 组件未直接引用任何引擎 API（全部数据经桥接层获得）

---

### User Story 2 - 拖动滑块预览渐进即时更新 (Priority: P1)

作为端到端使用者，我拖动任意调整滑块时，预览随之即时变化：低分辨率预览先行响应，高清预览在后台补齐后自动替换；我快速连续拖动时界面始终响应，最终显示的是我最后停下的那个值对应的结果。

**Why this priority**: 「调整即时可见」是照片编辑器的核心体验，也是桥接层「事件转发」职责的主干；依赖故事 1 的打开链路。

**Independent Test**: 模拟连续多次滑块事件（含快速连发与值回调晚到），校验状态层先回写低分预览、后回写高分预览，且最终状态与最后一次事件语义一致、旧版本结果被丢弃。

**Acceptance Scenarios**:

1. **Given** 已打开图片，**When** 界面提交一次滑块调整事件，**Then** 桥接层将数值转换为参数字典转发引擎，状态中的预览数据随后更新
2. **Given** 一次调整触发多级渲染，**When** 低分渲染完成回调先到、高清回调后到，**Then** 状态先呈现低分结果、再被高清结果替换
3. **Given** 用户快速连续提交多次调整，**When** 某些渲染回调晚到，**Then** 仅最新版本的结果被回写，迟到的旧结果被丢弃，界面不出现「回退闪烁」
4. **Given** 任一调整处理期间，**When** 界面读取绑定数据，**Then** 忙碌标志如实反映处理状态，供界面禁用输入或提示
5. **Given** 一次调整参数非法或引擎拒绝执行，**When** 事件转发完成，**Then** 状态回写可读错误消息，预览保持最近一次有效结果

---

### User Story 3 - 撤销/重做后界面与编辑状态一致 (Priority: P2)

作为端到端使用者，我点击撤销或重做后，预览回退/前进到对应状态，滑块位置也如实回到该状态的参数值；无可撤销/重做时我得到明确提示而不是异常。

**Why this priority**: 撤销/重做是非破坏性编辑闭环的一半，其界面一致性完全依赖桥接层的同步回写；依赖故事 1、2。

**Independent Test**: 模拟「调整 → 撤销 → 再调整 → 重做」事件序列，逐点校验状态中预览数据与滑块值和引擎当前编辑状态一致；空栈操作时校验错误消息回写。

**Acceptance Scenarios**:

1. **Given** 已有若干调整，**When** 界面触发撤销事件，**Then** 状态中的预览数据与各滑块值同步回退，与引擎当前编辑历史一致
2. **Given** 存在已撤销操作，**When** 界面触发重做事件，**Then** 预览与滑块值同步前进，与引擎当前编辑历史一致
3. **Given** 空历史或已全部撤销，**When** 触发撤销/重做，**Then** 状态回写可读提示，界面既有显示不变
4. **Given** 撤销/重做后的任意时刻，**When** 比对界面滑块显示值与引擎当前指令栈，**Then** 两者 100% 一致

---

### User Story 4 - 导出成品并获得进度与结果反馈 (Priority: P2)

作为端到端使用者，我在界面上选择导出位置与格式后，能看到导出进度，并在结束时得到成功或失败的可读反馈；失败不会让应用崩溃或产生误导性的成功提示。

**Why this priority**: 导出是工作流「打开 → 编辑 → 导出」的收口；桥接层在此承担「文件状态」子状态的事件转发；依赖故事 1。

**Independent Test**: 模拟导出事件并注入引擎进度/完成/失败回调，校验状态中进度、成功结果、失败消息的回写时序与内容。

**Acceptance Scenarios**:

1. **Given** 已打开图片，**When** 界面提交导出请求（目标路径与格式），**Then** 桥接层转发引擎并在状态中呈现进度
2. **Given** 导出成功，**When** 完成，**Then** 状态回写成功结果供界面提示
3. **Given** 导出失败（如路径不可写），**When** 引擎报告失败，**Then** 状态回写可读错误消息，应用不崩溃

---

### User Story 5 - 异常全程可读提示且界面零崩溃 (Priority: P3)

作为界面层集成者，我把界面接到桥接层后，任何引擎侧异常（加载失败、参数拒绝、渲染错误回调、导出失败）都已被桥接层转换为状态中的错误消息，我只需展示消息，无需自行捕获引擎异常或编写防御逻辑。

**Why this priority**: 错误隔离是「界面层零防御」承诺的兜底，价值建立在全部正向链路之上。

**Independent Test**: 逐一注入各类引擎异常与错误回调，校验每条路径都以可读消息回写状态且状态层不抛出未捕获异常。

**Acceptance Scenarios**:

1. **Given** 引擎同步抛出任意格式化异常，**When** 对应事件被触发，**Then** 状态回写可读错误消息，状态层无未捕获异常
2. **Given** 引擎经回调接口送达错误事件，**When** 回调执行，**Then** 状态回写可读错误消息
3. **Given** 任意错误发生后，**When** 用户继续正常操作（如重新打开图片），**Then** 应用恢复正常工作，错误消息随新操作清除

### Edge Cases

- 连续快速拖动滑块导致渲染回调乱序/迟到：MUST 按版本判定新旧，仅最新版本回写（新者胜），旧结果丢弃
- 打开新图片时旧图片的在途渲染回调仍可能到达：MUST 作废旧会话的迟到回调，不污染新会话状态
- 同一图片重复打开：MUST 重置为干净的初始编辑状态（滑块默认值、空历史提示一致）
- 处理期间用户继续提交事件：MUST 通过忙碌标志向界面暴露忙闲，由界面决定禁用或提示；状态层自身不丢失、不错乱事件
- 导出目标路径不可写或磁盘失败：MUST 回写可读错误，不留误导性成功状态
- 高分预览回调到达时用户已再次调整：MUST 以版本号判定丢弃过期结果

## Requirements *(mandatory)*

### Functional Requirements

**打开与呈现**

- **FR-001**: 桥接层 MUST 暴露界面可直接绑定的编辑视图状态，至少包含：预览图数据、直方图数据（RGB 三通道分布）、各滑块当前值、忙碌标志、当前文件名、错误消息
- **FR-002**: 打开图片 MUST 经桥接层转发引擎加载；成功后状态回写满足：低分辨率预览先行可用、高清预览随后自动替换、直方图同步刷新、各滑块重置为默认值
- **FR-003**: 打开失败 MUST 以人类可读错误消息回写状态，界面既有内容保持不变，状态层不崩溃

**调整转发与渐进呈现**

- **FR-004**: 每个滑块调整事件 MUST 由桥接层转换为参数字典转发引擎，并把引擎产生的预览更新回写状态（低分先行、高分后台补齐）
- **FR-005**: 桥接层 MUST 实现引擎回调协议（渲染完成/进度/错误），把事件转成状态回写；界面组件不得直接接触引擎
- **FR-006**: 在途渲染结果 MUST 按任务版本判定新旧，仅最新版本被回写（新者胜），迟到旧结果 MUST 被丢弃
- **FR-007**: 处理期间 MUST 通过忙碌标志向界面暴露忙闲信息，供界面禁用输入或提示

**撤销/重做与一致性**

- **FR-008**: 撤销/重做 MUST 经桥接层转发引擎，完成后预览数据与各滑块值 MUST 同步回写，界面显示与引擎当前编辑历史一致
- **FR-009**: 引擎报告无可撤销/重做时，MUST 以可读提示回写，界面既有显示不变

**导出**

- **FR-010**: 导出请求（目标路径与格式）MUST 由桥接层转发引擎；进度、成功、失败均以状态回写呈现
- **FR-011**: 导出失败 MUST 回写可读错误消息，不得残留误导性成功状态

**错误隔离**

- **FR-012**: 引擎同步异常与异步错误回调 MUST 全部被桥接层转换为状态中的可读错误消息；任何错误路径不得使状态层抛出未捕获异常
- **FR-013**: 新操作成功后，前次错误消息 MUST 被清除，避免陈旧错误误导用户

**胶水约束（架构红线，承自准则 I）**

- **FR-014**: 桥接层 MUST 是唯一同时引用界面框架与核心引擎的层（静态检查可验证）
- **FR-015**: 每个事件处理器 MUST 只做「参数转换 + 引擎调用 + 状态回写」三个动作；出现任何业务 if/else 分支即视为违规，逻辑 MUST 下沉引擎层
- **FR-016**: 层间传递 MUST 仅限原始数据与消息对象（参数字典、图像字节、进度事件），禁止传递界面组件或框架对象
- **FR-017**: 桥接层全部逻辑 MUST 可在无浏览器环境自动化测试

### Key Entities *(include if data involved)*

- **编辑视图状态（DevelopState）**: 界面的单一数据源——预览图数据、直方图数据、滑块值集合、忙碌标志、错误消息；其事件处理器是全部用户编辑动作的转发入口
- **文件状态（FileState）**: 打开/导出流程的界面绑定数据——当前文件名、导出进度、导出结果
- **渲染事件消息**: 引擎 → 桥接层的唯一通知载体（任务标识、阶段、进度比例、图像字节）；桥接层消费后转成状态回写

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 界面集成者仅依赖桥接层暴露的绑定数据与事件处理器，即可完成「打开 → 调整 → 撤销/重做 → 导出」全部界面接线，全程零引擎 API 直接调用
- **SC-002**: 打开图片后低分预览先行呈现、高分随后自动替换，直方图与滑块初值同步就绪，全程无需用户刷新
- **SC-003**: 连续快速调整后，界面最终呈现的结果与最后一次调整语义 100% 一致（无旧结果回退闪烁）
- **SC-004**: 撤销/重做任意序列后，界面滑块显示值与预览和引擎当前编辑状态 100% 一致
- **SC-005**: 全部引擎错误路径（打开失败、参数拒绝、渲染错误回调、导出失败、空栈撤销）100% 呈现为可读消息，状态层零未捕获异常
- **SC-006**: 桥接层全部自动化测试在无浏览器命令行环境一次通过（全绿），且界面组件代码改动不影响桥接层测试
- **SC-007**: 静态检查确认「同时引用界面框架与核心引擎」的源码文件仅存在于桥接层（唯一例外）

## Assumptions

- 引擎门面与回调协议按已交付的 001 契约（`specs/001-core-engine-layer/contracts/core-api.md`）提供；本特性对引擎层仅允许两处 additive 变更——只读查询方法（当前生效参数、已注册参数模式）与红线自检的导入链语义修正——不改动 001 契约既有签名与语义（决策依据见 plan/research.md D1/D2）
- 预览图向界面传递的具体编码形态（内联数据 URL 或静态资源 URL）由实现阶段确定，规格只约束「界面可直接消费」
- 单用户单会话：一次编辑一张图片；多图管理不在范围（设计文档已裁剪 Library 模块）
- 本特性仅交付桥接层（状态定义、事件转发、数据转换）与其测试；界面组件与页面属后续特性（里程碑 M4–M5 其余部分）
- 滑块的界面控件形态（拖动步长、松手时机）由界面层决定，桥接层只约定「收到事件 → 转发引擎」的单一契约
